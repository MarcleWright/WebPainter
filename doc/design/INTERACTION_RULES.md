# 选区编辑交互约定

范围: 当前交互的保持要求及后续性能优化验收。2026-11-11 弹窗与片段选区规则已实施并完成定向自动验证；独立复审、人工/Owner 验收仍 Pending，详见[本轮任务](../ai/tasks/2026-11-11_01_dialog-and-selection-interaction.md)。产品目标见 [性能方向](../product/PERFORMANCE_DIRECTION.md)。

## 移动的三个阶段

| 阶段 | 用户看到的行为 | 正式状态要求 |
| --- | --- | --- |
| 按下并开始移动 | 选区内容进入可拖动状态, 原位置显示应有的底图 | 无移动的点击不能留下修改或多余撤销 |
| 拖动中 | 选中内容与轮廓持续跟随指针, 保持正确图层遮挡和效果 | 允许临时预览; 不能把每个采样点写成历史步骤 |
| 松手 | 保持最后位置, 平稳交接为正式结果 | 一次实际拖动仍对应一次撤销 |

实时预览不是简单贴在整个画面最上面。被选内容仍属于原来的图层, 应服从该层的蒙版、透明度、混合、剪贴及上方调整。

## 保持现有操作习惯

- A 到 B 再到 C 的连续两次拖动, 不能在 B 留下第二个孔洞。现有 `moveSelection.test.ts` 已覆盖基础情形。
- 两次独立拖动分别可撤销到 B 和 A。不要为了复用浮动选区而把它们合并为一个跨操作历史步骤。
- 取消当前拖动且仍拥有资源时保持开始时的图层和选区；外部写入、对象替换或目标移除后只清理本次预览，不以旧快照覆盖外部新状态。不新增确认按钮。
- 上述取消指 Esc/切工具等取消意图。原有 CanvasView 将 pointercancel/lostpointercapture 转为 up, 原型应按最后有效位置至多结束一次, 不将这些浏览器事件一律改成 Esc。具体失效行为见 [任务 02](../ai/tasks/2026-11-05_02_4k-selection-preview-prototype.md)。
- 复制拖动、无位移松手、移出画布、切工具等需作为回归场景逐项验证, 不把未验证行为写成已完成。
- 原有 Shift 约束、缩放、选区轮廓跟随等需要保留。移动输入可以合并为最新位置; 笔刷仍需保留必要轨迹采样。

## 单层像素选区的 Move 规则

单个像素层且有像素选区时，Move 从画布内任意起点发起选中片段移动，包括透明洞、选区外点和低 Alpha；down、hover/lift 使用同一资格，保留显式自动选层、变换手柄和锁定优先级。空片段或锁定拒绝不能退入整层移动；多选、mask/channel/Quick Mask 不套用新片段资格。

片段 Alpha 是 `min(源 Alpha,选区覆盖率)`，不反复相乘。按实现审查 F1 修正：非 Alt 的原位剩余 Alpha 为 `max(源 Alpha-选区覆盖率,0)`；例如不透明像素的半覆盖移动留下半覆盖、移走半覆盖。目标位置仍按 source-over 放置；不要求片段与余量在原位叠加重建源 Alpha。Alt 保留源像素。轮廓覆盖率来自本次片段 Alpha，保留透明洞及原选区范围，不加载整层透明度或烘焙效果。低覆盖片段没有 0.5 等值边时显示非零边界，正式选区仍保留原数值。

实际位移才显示临时贴合轮廓；GPU 和 CPU 回退均用私有像素预览，不写正式选区。松手把像素和贴合选区作为一条 Move 历史提交，撤销恢复原宽松选区。单击、零位移、返回起点和空片段不收缩选区或增加历史。临时轮廓一次建立后平移，正式像素/轮廓不用每个 pointermove 重建快照；浮动缓存失效后低 Alpha 仍可重新提取移动。Ctrl/Cmd+点击图层缩略图的整层透明度命令保持独立。

## 预览交接与失败

后续方案若加入异步处理, 需明确目标文档、图层和交互身份。取消、关闭或切换文档后到达的旧结果不能覆盖新状态。提交失败应有可恢复的结果, 不允许仅清掉预览让图像消失。

这部分是已选主线的正确性要求, 尚未引入新后台任务。有限原型的提交、取消与失效分支已在 [任务 02](../ai/tasks/2026-11-05_02_4k-selection-preview-prototype.md) 冻结; 超出原型范围的日常工作流后续定义。

## 与 PhotoCraft 的区别

PhotoCraft v0.20.2 的浮动选区可在松手后继续保持, 直到放下或其他命令触发写入。可以借鉴内部状态管理, 不直接采用其历史分组方式。源码和边界见 [对照](../architecture/PHOTOCRAFT_REFERENCE.md)。
