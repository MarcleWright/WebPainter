# ADA 画板创建、WP 待命与 Web 打开提速

## 状态与目标

2026-11-18。**本地交付完成。** 阶段 0 至 E 的设计和实际证据已按范围独立核对。ADA 画板分支最终代码 `46659d1`，固定 WP 包 `01006e09…318f`。正式环境、Desktop 发布包与 Owner 设备体验待单独验收。详见[执行台账](2026-11-18_01_execution-loop.md)。

用户点击「画板」后应尽快看到 WP 的新建窗口。打开已有画板应尽快显示正确版本并能落笔，返回 ADA 后再次打开应省掉重复启动 WP 的等待。继续使用全屏 iframe 和底部悬浮提示词／模型面板。后台自动保存期间应保持正常绘画和编辑。

## 已有证据

- **用户观察。** 正式服务器 Web 打开画板慢。此前删除残留 4K 图层后，ADA 与独立 WP 打开后的绘画体验接近。当前线上点击到首笔可画的分段耗时未知。
- **源码核对。** ADA 的打开流程依次读取文档元数据／恢复状态、挂载并握手、请求 native 内容。元数据路由和内容路由都调用会整读并校验文件的 `readDrawing`。客户端还校验下载的内容 hash，WP 同步检查 native 块并重建图块。返回时先关闭 WP 文档，再销毁 iframe。实际 HTTP 缓存命中及各段耗时待测。主要入口为 ADA 的 `apps/api-node/src/drawing-routes.ts`、`artifact-store.ts`、`apps/web/src/editor/controller.ts`、`drawing-client.ts` 与 WP embedded 的 `src/embedded/editor.ts`。
- **本机实测。** 用校验过的当前固定 codec 在内存创建空白 `1920 × 1080` 与 `4096 × 4096` RGB8 文档，native 均为 **1,178 字节**，各含一个空图层。WP 状态栏的 `Doc: 64.0 MB` 由 `4096 × 4096 × 4` 得出，是一张完整 RGBA8 画面的 **64 MiB** 估算。实际文件字节数随已分配的图层图块变化。性能记录分别使用正式 native 字节数及实际内存采样。
- **历史边界。** 已有图块内容边界缓存、大画笔与变换预览、透视预览、Worker 确认及吞吐优化。以相同文档和环境重新测量后再引用数字。PhotoCraft 原生 Rust 源码作为设计参考，浏览器收益由实测确认。

## 分阶段任务与验收

| 阶段 | 范围、归属与最小验收 |
| --- | --- |
| **0 · 固定基线与复现** | 在隔离环境用固定 WP 包复现空白板、多层 4K、立即重开和修改后重开。记录版本、实际传输字节、各段耗时与内存。用本地 Web 跑通全链路，加一组可控慢网络模拟正式 Web 路径。保留现有测量作为历史对照。 |
| **A · 画板命名与 WP 新建入口** | ADA 用户可见名称统一为「画板」，已有用户自定义标题和存储字段保持兼容。点击创建入口直接进入全屏 WP，在 WP 中复用新建窗口及常用像素预设。初始选择 `1920 × 1080`，沿用现成的方形、竖版、2K／4K UHD 等适用预设并允许自定义，按 ADA 当前尺寸合同校验。嵌入模式固定 RGB 8 位。只暴露与创建合同匹配的字段。WP 通用 UI 改动进 main，embedded 适配用有限回调交出确认后的尺寸，由 ADA 持久化 artifact 并放置节点，再在同一 iframe 打开画板。验收取消零写入、预设和非方形自定义尺寸准确、超限拒绝、重复确认只生成一份画板和节点、已有画板直接打开。 |
| **B · Image node 工具栏** | 「继续编辑」改为「AI 编辑」，采用魔法棒图标，沿用现有 AI 编辑入口。在同一工具栏新增「画板中编辑」，读取同项目可读原图，按方向校正后的原图尺寸创建 RGB8 画板，复制源图像素为首层，正式版本和投影确认后自动打开。复用 WP 导入／编码能力，确认需要通用 codec 扩展时走 main → embedded → ADA 固定包。验收透明 PNG、带方向信息的 JPEG、原图未被更改、跨项目／无权／不支持或超限输入拒绝，以及打开失败后能重试同一画板。 |
| **C · WP 实例待命** | 将 WP 实例与画板会话分离。返回时完成必要的保存并关闭文档，释放其图层、历史和渲染资源，隐藏 iframe 并还原 ADA 焦点。每个当前工作区最多保留一个待命 WP 实例，后续新建或打开复用它。切换账号、项目或实际离开工作区时销毁，真正的连接续期保留现有连续性。验收重复开关与跨画板切换、隐藏态快捷键归还、会话与资源释放、退出及授权变化、关闭失败保住草稿。若需要扩展嵌入端口，按固定包路径交付。 |
| **D · 已有画板加载** | 先在 ADA 拆出轻量元数据读取并验证授权、正式版本及恢复语义。正式载荷路径保留完整性校验。在版本匹配时可先显示缩略图和加载状态，实际能落笔时才标为就绪。若分段证据表明重复下载仍主导耗时，再评审有界进程内缓存。若 WP 解码或首帧主导，再到 WP main 优化对应热点。验收首次／立即重开／修改后重开的首笔可画耗时，以及并发更新、恢复、损坏文件和跨身份隔离。 |
| **E · WP 绘画和变换复测** | 在 WP main 用相同 native、DPR、笔刷和输入对照独立版与 ADA iframe。大笔刷记录输入到显示、长帧和笔画结束。Ctrl+T 分计 Enter 到 Worker 完成、正式数据安装、正确画面呈现。覆盖仿射、透视与自动保存期间继续输入。只对测得热点实施局部修复，保持正式像素和一次撤销语义，再经 embedded 同步给 ADA。 |

## 状态、持久化与并发约束

- **确认与重试。** 确认后冻结目标项目、Canvas ticket、artifact ID、节点 ID 和创建输入。从原图创建时额外固定源 ID 与 hash。重复点击加入同一次操作。结果不明确时通过原身份核对。投影失败时保留已提交 artifact 并重试原投影。开窗失败时重开同一个 artifact。上下文离开后旧回执不能在新项目放置节点或打开编辑器。
- **从图创建。** 在含首层的正式版本确认前，空白中间内容不能成为成功交付。Reviewer 需核查源图权限、方向、透明度、版本变化和首层 native 持久化。已有 artifact 消费合同与正式内容的版本校验继续有效。
- **待命与关闭。** 按「打开中 → 编辑 → 关闭中 → 待命」串行切换。关闭成功以后旧文档 binding、generation、保存回执及面板结果失效。关闭失败保持当前文档可恢复，不能提前隐藏或销毁。待命只复用 WP 实例，不保留已关闭文档、旧生成面板状态或后台保存定时器。
- **正式内容与缓存。** 元数据包含同一正式版本的 revision、content hash、native ID 和恢复候选。正式内容必须匹配已授权的读取。并发变更时重新确认，不能混用不同版本。若启用缓存，以服务、账号会话、Profile／实例、项目、artifact 和正式版本标识隔离，设字节预算和 TTL。切账号或离开工作区立即失效。恢复候选继续走独立校验与用户选择。
- **自动保存。** 延用已验证的输出互斥、稳定检查点、原 operation 回执与显式关闭截止点。保存期间继续输入，新回执确认其对应检查点，旧回执不能把后续修改标记为已保存。预览显示与编辑就绪状态分开。

## 验证与评审

- **版本及自动化。** 使用仓库现有 WP 验证预设和构建检查。ADA 跑 Canvas 创建与节点工具栏、绘图 controller／恢复／保存、API 创建与发布的定向用例。改到存储时，验证 SQLite 和 PostgreSQL 下的重放、事务及并发读取。更新固定包时验证 manifest、资源完整性及 Web 构建。
- **实窗与性能。** 拆分服务端元数据／磁盘读取、iframe 加载与握手、下载与校验、RPC 交接、WP 解码、首个正确显示帧和首笔可响应。使用同一空白小板和同一多层 4K 样本，每种关键路径至少 5 次。报告中位数、最慢样本、实际载荷字节数和内存峰值。区分首次启动 WP、WP 待命后打开同板和打开另一板。对照变更前后，基线后再确定各路径的数值改进目标。
- **环境。** 隔离测试数据和数据库。ADA Web/开发 Desktop 的入口参考 `start-dev-web.bat` 与 `start-dev-desktop.bat`。主开发 Web 地址为 `http://127.0.0.1:18199`，启动器改动仍属原工作树。隔离工作树使用核对后适用的启动方式。正式 Desktop 入口 `start-prod-desktop.bat` 绑定 `D:/AutoDesignAgent-Release`，按实际包版本另验。本任务的实验使用本地夹具和替代 Provider，生产访问、真实模型调用与发布另行授权。
- **人工验收。** 先在本地 Web 完整走通三条打开路径，开发 Desktop 实窗复核新建、保存返回和重开。Owner 自有作品、真笔、IME、高 DPR 及正式 Web 与正式 Desktop 体验分别记录待验或实测结果。正式环境的发布验收沿用独立授权。
- **Reviewer 焦点。** 核对 A/B 的唯一创建和耐久首层、C 的待命／关闭与焦点归属、D 的版本和恢复准确性、E 的画面交接与自动保存回归。按实际版本区分方案评审、代码评审、自动化、实窗和 Owner 验收。

## Context Delta

- 画板创建用 WP 原有预设 UI，ADA 在确认后持有正式创建与投影。
- 返回 ADA 后关闭文档，WP iframe 在当前工作区内待命。
- 正式 Web 打开性能以点击到首笔可画验收。优先量化重复启动与元数据整文件读取，再决定缓存或进一步的 WP 优化。
