## Task Brief

在保留 Celenne 文档、历史和文件管线的基础上, 验证“稳定底图 + 浮动选区 + 位移”的 WebGPU 图层内实时合成能否改善常见 4K 局部移动。原型先覆盖 RGB 8 位普通像素层及一组必要效果组合, 交付可复查的性能、像素和历史行为证据, 决定该主线是否值得扩展为正式功能。

建议验证预算为 2-3 人日, 是限制投入的评估预算, 不是完成承诺。预算内证据不足应报告 Inconclusive, 不静默扩大为完整引擎改造。

复杂度约定: 本项目主要服务约百名用户, 本轮收缩验证矩阵、工具建设和正式化验收负担, 不削减下述核心优化。原型用最少可信证据回答“是否明显跟手、结果与操作是否正确”, 不提前建立完整性能/兼容性验证体系。

## Goal

- 拖动期间实时可见, 位置更新不反复改写正式图层/选区像素或重新上传整块浮动内容。
- 保持原图层的合成关系, 预览与松手结果一致。
- 保留一次拖动一次撤销、连续移动不重复挖洞、取消恢复开始状态。
- 使用同条件基线证明收益, 明确未覆盖范围; 不以 GPU 已开启、函数变快或界面能启动代替验收。

## Evidence And Root Cause

源基线: `a659900384aee878f01e4caae183a666acc7959b`。既有 [4K 评估](../../engineering/4K_SELECTION_ASSESSMENT.md) 中, 中/大选区单次移动平均约 24/87ms, 主要 CPU 热点为 stampFloat、内容边界扫描、缩略级别重建及图块写入。

## Change Contract

### Must change

- 用私有稳定底图/片段准备预览, 在现有 GPU 合成入口增加浮动来源和位移表达。底图与片段先在原图层内部组合, 再应用该层及上方的效果。
- 移动只更新最新有效位移与显示代次; 输入合并只作用于移动, 不减少笔刷必要轨迹。
- 松手才生成正式像素和选区结果, 沿用现有历史命令; 取消和失效有明确清理路径。
- 配套使用正确失效的边界/缩略缓存及 UI 通知延后, 只处理影响本原型的热点。
- 固定有限样例、轨迹和计时边界, 先取得旧路径基线和结果参考。复用现有测试、调试和窗口能力, 必要时只补小脚本/计数, 不建设通用基准采集平台。

### Must preserve

- 当前 alpha 与 coverage 的像素规则、整数移动取整、原图层坐标、可见性和锁定语义。
- A 到 B 再到 C 不在 B 留孔洞; 两次独立拖动分别可撤销到 B 和 A, redo 可恢复。
- 无位移点击不增加历史; Alt 复制移动、Shift 约束及选区轮廓跟随保留。
- 未支持格式/后端/层组合在进入交互前走现有路径, 不静默丢失图层效果。

### Scope And Non-goals

允许的未来实施 owner: `src/tools/moveTool.ts`, `src/rendering`, `src/gpu`, 必要的 `CanvasView` 输入和现有 editor/session 交互连接, 以及有证据需要的 bounds/TiledRaster 缓存小改动。测试放现有 tests/ 与专用验证脚本; 如需入口脚本只增加验证入口, 不升级依赖。

不改 PSD/原生存储、持久文档版本、业务图层种类、品牌/包身份、ADA 集成、笔刷算法或 Ctrl+T。无新 Rust/WASM 依赖、全局状态管理、通用任务调度/事务框架或整套渲染替换。

原型通过显式本地实验入口启用, 默认不替换真实用户工作流; 必要时可最小增加构建期验证开关, 不新建配置系统。仅在独立 profile 和合成文档运行, 关闭该 profile 的自动保存。拖动中保存/导出/自动保存并发的一致性属于正式化前必须补齐的范围, 本任务不声称覆盖, 不把实验入口默认开放给日常文档。

原型不要求 16/32 位、CMYK/Lab、复杂组/剪贴/样式的优化全覆盖。它们必须有明确支持判断及原路径回退, 不能被宣称已通过。完整覆盖另行立项。

## Ownership And Invariants

以下预览不变量与性能门槛适用于已启用且受支持的 GPU 原型路径。未支持场景保留旧路径行为, 不宣称满足原型的零改写或性能门槛。

1. 正式真源仍是原 session 的 doc、目标层 raster、selection 和 history。预览资源仅是当前交互的显示输入, 不插入业务图层或形成另一份持久真源。
2. 交互绑定 session.id、doc.id、layer.id、doc.rev、源 raster 对象及 version、selection.mask 对象及 version、本次 interaction token。doc.rev 只承担结构/属性核对, 不能替代像素版本。
3. 正式图层和选区像素在拖动中不因预览改变。源内容/属性/选区发生其他修改时, 放弃旧预览, 保留新的正式状态, 不能恢复旧快照覆盖它。
4. 每次呈现的受影响区域使用同一个有效位移/显示代次。计算未完成可保留上一完整预览, 不能将不同位置的图块长期拼接。
5. 提交前再次核对身份。正式图层、选区和对应历史步骤要一致完成; 失败时恢复本次提交前状态, 无半写入或多余历史。
6. GPU 资源有 device 与交互 owner。结束/失效释放本次资源; 可有界复用既有 floating 数据以保持连续拖动语义。关闭文档后不保留本原型资源。

## Frozen Decisions

- 主线是浮动选区状态 + 稳定资源的 WebGPU 图层内合成, 不再比较哪一种整体路线才开工。
- CPU 保留作结果参考、正式提交及未支持场景回退; 批量复制只能辅助准备/提交, 不能以继续每采样改写正式 raster 代替主线。
- 原型只优化 RGB 8 位的下列矩阵, 不改现有手感和历史分组, 不采用 PhotoCraft 跨拖动后再 drop 的历史规则。
- 此时尚无优化后的性能证据。30fps 是体验参考目标, 本原型以同条件前后对照、真实窗口体验和结果正确性共同判断, 不设置多项缺乏充分基线依据的性能硬阈值。

## Failure And Lifecycle Semantics

| 触发 | 预期结果 |
| --- | --- |
| 不支持的格式/效果/后端 | 开始前选择原路径, 记录回退原因; 必测 GPU 场景不得靠回退算通过 |
| 准备/上传失败 | 正式数据和历史不变, 清理局部资源并报告原因; 不在半准备状态继续显示 |
| Esc、切工具、切换/关闭文档 | 结束本次预览, 不产生历史或把旧结果落到新目标 |
| 源层/选区改变、层被删除或锁定 | 旧交互失效, 保留当前正式修改; 旧回调不得覆盖 |
| pointercancel / lostpointercapture | 当前 CanvasView 将它们转为 up; 原型沿用最后有效位置结束, 身份有效时至多提交一次, 与后续 pointerup 去重 |
| 松手写回失败 | 正式数据和历史保持提交前状态, 不留孔洞/半提交; 清理预览并显示错误 |
| 提交前 device lost 或旧上传/显示结果晚到 | 丢弃本次预览, 正式数据/历史不变; 清理失效资源, 后续操作可走原后端回退 |

已成功正式提交之后才发生设备丢失, 只清理显示资源并走后端恢复, 不能回滚已经确认的文档/历史。

若引入异步步骤, 以 interaction token 加目标对象/版本校验结果, 不能靠读取最新版本给旧操作续命。原型不要求新增后台任务系统。

以上是代码应遵守的正确性边界, 不是要求原型构建完整故障注入体系。必要的身份检查、取消和资源释放仍需实现; 设备丢失等完整验证后移。

## Acceptance Scenarios

### A. 固定场景

主样例固定为非均匀 3840 x 2160 sRGB RGBA8 图像, 选区初始坐标 (128,128)。记录实际源层 ID, 确认 active layer 是被测 pixel 层, 避免误测调整层。不展开尺寸 x 缩放 x 效果的完整排列。

| ID | 场景 | 范围 |
| --- | --- | --- |
| C0 | 普通不透明照片层, 硬边矩形选区 | 1536 x 1024、3072 x 1728; 固定 25% 缩放作前后对照 |
| C1 | 同一 4K 图, 背景 + 活跃照片层 + 上方非默认 Curves; 照片层 opacity=0.65、Multiply、包含 0/0.5/1 区域的 raster mask | 1536 x 1024、25% 缩放, 只保留一个必要效果组合 |
| C2 | 一个小型 RGBA8 fixture, 含透明/半透明内容和分数 coverage 选区边缘 | 只核对像素和历史, 不进入 4K 性能矩阵 |

C1 的 mask 默认开启且保持固定坐标, 本任务不实现移动 mask 工具。100% 缩放做一次基本手工观察即可, 不重复全套性能测试。任意智能对象/组/剪贴或未支持样式走原路径。

### B. 像素与历史门槛

- 在改源代码前, 从实际旧 MoveTool 和原合成器取得相同输入/关键位移的参考, 保存 source hash、场景和输出校验值。不得复制新算法写一个同形 mock 作为 oracle。
- C2 最终 raster/selection 全量与旧路径逐样本一致; C0/C1 检查原位置、新位置与边缘关键区域, 层/蒙版属性不变。Celenne 原有 coverage 乘 alpha 的规则不变。
- 固定几个关键位置, 在相同设置下对照预览、松手和旧路径画面, 检查轮廓、孔洞、遮挡和效果。发现差异需定位, 不能只凭肉眼认为差不多。全矩阵 GPU 读回及精细误差阈值留到正式化, 原型不为此另建图像对比系统。
- 必测 A->B->C、分别 undo/redo、第二次拖动中取消及无位移。Alt 复制、Shift、边界和重复 up 做一次基本回归, 复用现有测试, 不为每种输入建立专用设施。
- 提交交接无回跳原位置, 受影响区域不混合不同代次。只有轮廓跟手或松手后才看到正确内容均不通过。

### C. 性能与实现核对

- 在同机器、同构建模式、同窗口和缩放下对照 C0/C1 的固定拖动。首选既有测试机器, 记录后端与样例; 开发模式可用于原型, 不能把其结果标作生产 FPS。
- 记录移动处理、首次准备、松手稳定时间的前后数据, 并在真实窗口连续操作/录屏, 确认大选区明显跟手且不再持续分块追赶。30fps 为参考目标, 有可信完整更新统计则报告; 没有时如实写“未量得实际 FPS”, 不把 rAF/指针更新算成画布帧率。
- 不再把 P95<=8ms、提升>=70%、准备退化<=20% 等多项数字作为原型硬门槛。初次准备或松手出现明显新卡顿仍需记录并解释, 不能藏在平均值里。
- 核心实现必须核实: GPU 路径实际命中, 拖动期间正式 raster/selection 写入为 0, 位移更新不反复全量上传/重建选区像素。用现有调试能力和少量局部计数确认, 不以仅有 GPU renderer 名称代替。
- 重复拖动/取消并关闭测试文档, 检查基本资源释放和错误日志。专门 GPU 句柄审计、20 轮量化泄漏测试留到正式化, 不要求新建资源追踪器。

## Result And Decision Gate

交付一份简短结果: 做了什么核心改动, C0/C1 前后耗时和窗口体验, C2/历史检查, 已知问题与下一步。原始材料放本地 material; 稳定结论回写工程评估。不要求完整 benchmark 仪表盘或资源报表。

- Go: 核心 GPU 路径跑通, 必测范围的结果/操作正确, 实窗拖动明显改善且有前后证据。若未测得实际 FPS, 不宣称已达到 30fps。可以讨论正式化, 不等于发布通过。
- Revise: 具体局部问题可在既定 owner 内解释并修正, 明确剩余成本和证据, 不宣称已通过。
- No-go: 必须省略图层语义、改变正式像素规则或大幅超出既定核心边界才能满足, 提交新的评估而非自动重构。
- Inconclusive: 时间预算、环境或证据不足, 列明缺失项和下一步最小验证。
