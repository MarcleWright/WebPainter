## Task Brief

[Task 02](2026-11-05_02_4k-selection-preview-prototype.md) 的受限原型已通过代码复审与用户试用, 但新移动路径仍依赖 DEV 和全局实验标记, 普通生产启动继续使用旧路径。本任务将已验证路径接入正常运行: 支持时默认使用, 不支持时自动回退, 用户不选择“原版/优化版”。同时补齐 Move 与保存、导出、恢复快照和关闭的最小交接, 恢复正常启动及自动保存配置语义。

## Goal

- 普通生产构建、正常开发启动和 Start-WebPainter.bat 均无需开关即可使用同一优化能力。
- 保留图层合成、像素结果、一次拖动一次撤销及自动兼容回退, 不丢失已取得的性能收益。
- 显式保存/导出读取已确认的内容; 自动保存不打断拖动; 关闭和取消不留下临时像素或多余历史。

## Evidence And Root Cause

- 已提交基线为 ec5b6ee; 工作区另有用户授权创建的 Start-WebPainter.bat、scripts/start-current.mjs、current-source-host.cjs 及对应文档, 执行前以 git status 为准, 不丢弃这些未提交工作。

- GPU 合成器与 RenderEngine 已支持浮动来源、稳定图块、CPU 回退和原图层效果; 本任务复用它们, 不另建渲染器。
- fileOps.writeDocument 目前只先 commitTextEdit; exportAs 和 autosaveNow 各自直接序列化 doc。autosave 定时入口检查 currentTool.busy, 直接入口及 yield 后仍需核对目标状态。closeSession 在 modified 判断前未统一处理 Move。
- 保存过程含文件对话框、序列化和异步写盘; Session.markSaved 使用完成时的 history.current。需避免写盘期间后续编辑被误标为已保存, 不扩展为通用文件事务系统。
- 现有支持边界: RGB 8 位普通顶层像素图层、25% 及更高缩放和已支持的 Curves/蒙版/混合组合, 受 GPU/atlas/视图能力限制。16/32 位、组/剪贴/样式及更低缩放等继续按原判断回退。

3. 为当前 Move 增加或复用最小的“结束并返回结果”入口, 接入现有 Tool/Editor/Session。必须能区分无交互、成功提交、取消/失效及失败, 不能把 void up 或被内部吞掉的错误当成功。仅为 Move 适配, 保留文字、Ctrl+T 等已有生命周期规则。

## Ownership And Invariants

主要 owner: MoveTool, Tool/Editor/Session 的最小交接, fileOps/autosave, 必要的 CanvasView 交互收尾, 启动及验证脚本。GPU/RenderEngine 只作能力判断、失效与生命周期确有需要的小改动; 领域边界见 [INTERACTIVE_PREVIEW](../../architecture/INTERACTIVE_PREVIEW.md)。

- 交互绑定原 session/doc/layer、源 raster/selection 身份和版本; 沿用原型有效性校验, 不靠读取新版本为旧预览续命。
- 文件操作捕获目标 session, 不能因对话框期间切换活动文档而写到另一份作品。目标关闭或交互失效时停止, 不把旧结果落到新目标。
- 每份输出对应序列化时的一份一致、已确认检查点。沿用现有快照/序列化能力或最小目标保护; 不建立持久版本服务, 不用不完整克隆丢掉 PSD 元数据、图层参数或资产引用。
- 异步写盘完成后, 只有当前状态仍对应实际输出检查点才能标记 clean/清除对应 recovery; 后续编辑继续保持 modified。导出副本不把原文档标记为已保存。

## Failure And Lifecycle Semantics

| 触发 | 明确行为 |
| --- | --- |
| 显式 Save / Save As / Save Copy / Export As / Quick Export | 在目标会话的有效 Move 上提交最后有效位置, 至多新增一次历史, 再进行输出; 选路径等异步步骤后, 实际序列化前重新核对目标并固定检查点。取消文件对话框只取消文件操作, 不回滚已确认的移动 |
| Move 写回失败或源身份失效 | 文件操作返回失败/取消, 不继续输出旧状态并显示成功; 保留正确的当前正式状态, 清理预览。通知异常发生在成功入栈后仍沿用完整提交语义 |
| 自动保存到期或直接 autosaveNow | 不替用户提交或取消正在进行的移动; 跳过该目标并保留后续重试机会。yield 后、序列化前再次检查, 不使用其他活动文档的 busy 状态代替目标检查 |
| Esc、切工具、切文档、关闭文档/应用 | 取消尚未提交的 Move, 不新增历史; 关闭在 modified/保存提示判断前结束该预览, 再沿用原有 Save/Don't Save/Cancel 流程。已确认的编辑不因取消预览丢失 |
| 对话框或写盘期间继续编辑/切换/关闭 | 输出不混合两个检查点、不重定向目标; 已有输出完成不将较新编辑误标为 clean, 不删除其较新恢复数据。关闭目标后的晚到 UI/状态回写需核对原会话仍存在 |
| GPU 在提交前失效 | 丢弃未提交预览, 正式内容和历史不变; 后续可走兼容路径。提交后失效只恢复显示, 不撤销已成功编辑 |
| 不支持的场景 | 开始前自动兼容回退, 操作结果正确; 不承诺该场景获得同等性能收益 |

本轮只落实这些具体交接, 不把所有工具、所有输出消费者改造成新框架。切片导出、Duplicate Document 等旁路若会在 Move 期间读取 doc, 必须最小复用同一目标交接或明确拒绝忙状态; 不得遗留可输出陈旧内容的入口, 也不扩展它们的功能。
