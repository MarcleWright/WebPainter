# AI 协作规则

## 工作边界

- 从根 AGENTS.md、文档入口和 AI_CONTEXT 进入, 按任务读取 owner 层。先检查代码和现象, 不只按任务文字推断实现。
- `docs/` 保留上游体系。fork 的需求/差异/研究归 `doc/`, 不自动迁移或改写上游文档。
- 按用户当前授权执行。方案、评估、实现、提交/推送、发布与人工验收分别记录; 文档任务不自动扩大为代码优化。
- 保留无关改动, 不操作相邻 ADA 项目的业务数据或真实服务。本项目接入 ADA 需要单独契约。

## 文档维护

| 改动 | 主要归属 |
| --- | --- |
| 产品范围、价值、优先级 | product |
| 模块、接口、数据 owner | architecture |
| 可见操作与状态 | design |
| 环境、测试、证据和已知问题 | engineering |
| 未提升的原始输入 | material, 默认本地 |
| 当前上下文、任务、决策和历史 | ai |

每项稳定事实只有一个主要 owner。日志和上下文通过链接引用, 不重复粘贴整份评估。全量文档治理仅在结构/跨层真相变化时进行; 普通代码任务更新对应 owner 和必要的 DEV_LOG/AI_CONTEXT。

## 记录与验证

- 任务按日内编号, 一项任务一份详细记录。按风险决定规格重量, 不创建大量空模板。
- 实现、代码复审、用户体验与发布验收分别记录; 文档或自动检查通过不替代其他验收。
- 有 durable 变化时记录 Context Delta; 重要决策写 decisions, 不能仅放聊天。
- 自查不是独立审查。只有明确要求的独立审查才建立相应 reviewer 记录; 不自动建立长任务执行循环。
- 验证引用 [TESTING](../engineering/TESTING.md) 的预设, 明确本轮已跑、既有证据和未执行项。
- 所有新文档采用 UTF-8, 优先无 BOM, 交付前核对链接、乱码、原始材料忽略规则和 diff。
